# v0.2.2 — Verified monitor_v1 byte accounting and replay

Добавлен явный профиль `byte_semantics: "3proxy_monitor_v1"` для штатного
формата 3proxy-setup. Исправлено направление полей `%O|%I`: upload/download.
Сумма сегментов проверена на реальном upstream 3proxy 0.9.5 без logdump и с ним:
513 байт upload, 2049 байт download; промежуточные записи не удваивают итог.

Переход только семантики из unknown/delta сохраняет source id и историю.
Новая offline-команда `replay-3proxy` восстанавливает сохранившиеся plain-логи:
добавляет ранее пропущенные строки и исправляет NULL/переставленные байты через
UPSERT по прежним generation+offset. Повторный replay не дублирует события.
Работа одновременно с коллектором блокируется writer lock.

Включает исправление не-UTF-8 текста из v0.2.1. Можно установить сразу поверх
v0.2.0. Инструкция: `docs/upgrade-0.2.2.md`. Схема SQLite остаётся v1.

Ограничения: только подтверждённый monitor_v1; неподдерживаемые форматы не
угадываются. Replay не восстанавливает удалённые или gzip-логи. Остаток строк
с неизвестными байтами выводится отдельно. Копии архивов с новой файловой
идентичностью не следует подмешивать в glob: это не дедупликация по содержимому.

Проверки: Windows/Linux unit и MCP integration, runtime 3proxy/logdump на Linux,
повторный replay, source identity, writer lock, архив, SHA256, Gitleaks и ревью.
