# v0.2.1 — Resilient 3proxy log decoding

Некорректные UTF-8 байты в свободном клиентском тексте больше не приводят к потере
всей записи. Числовые поля проходят прежнюю строгую валидацию; offsets считаются
по исходным байтам, повторный запуск не дублирует записи. Сырые строки не сохраняются.

Схема БД и конфигурация совместимы. Уже пропущенные строки требуют отдельного
восстановления из сохранившихся логов; этот релиз не сбрасывает cursors.
`log_pending_bytes` остаётся индикатором незавершённого чтения.

Проверки: regression tests для повреждённого текста/числовых полей и offsets,
полный Windows/Linux suite, MCP integration, Linux smoke, ревью и Gitleaks.
